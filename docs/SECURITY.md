# Supabase 보안 전환

프로덕션 DB의 세 테이블은 RLS가 활성화되어 있으며 관리자 PIN 검증 정책을 사용합니다.

## 배포 전 목표 정책

- `anon`: 활성 선수와 확정 경기 결과 읽기만 허용
- 올바른 관리자 PIN을 요청 헤더로 제공한 접속: 선수·경기·참가자 생성, 수정, 삭제 허용
- 서비스 역할 키는 브라우저 번들에 절대 포함하지 않음

관리자 PIN 원문은 저장소나 데이터베이스에 저장하지 않습니다. 앱은 사용자가 입력한 PIN을 메모리에만 유지하고, 데이터베이스는 `supabase/migrations/20260901163000_secure_admin_pin_rls.sql`에 기록된 SHA-256 해시와 요청 헤더 값을 비교합니다. PIN을 바꿀 때는 새 해시로 별도 마이그레이션을 추가합니다.

## 공개 키

`VITE_SUPABASE_PUBLISHABLE_KEY`는 브라우저 사용을 전제로 한 공개 키입니다. 데이터 보호는 키 은닉이 아니라 RLS 정책으로 수행합니다. `service_role` 키나 데이터베이스 비밀번호는 프런트엔드 환경변수에 넣지 않습니다.
